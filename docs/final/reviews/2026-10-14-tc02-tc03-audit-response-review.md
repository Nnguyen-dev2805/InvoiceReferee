# Review of the TC02/TC03 agent audit

Verdict: **NEEDS_REVISION**. The browser runs are useful failure evidence, but the harness loses the intended company context, one proposed fix is incorrect, and the report overstates completed browser checks.

Checked on final HEAD `bd9e8769` with concurrent uncommitted linking changes. No application changes, provider calls, DB mutations, resets, server restarts or commits performed in this review. CodeGraph reported current source; coverage tool unavailable, coverage UNKNOWN. Relevant snippets and omitted harness ranges were read directly.

## Findings verified

1. **Environment:** current Settings has no missing LIVE names; X-Kiro base URL resolves to `https://api.xkiro.com/v1`, model `qwen/qwen3.7-flash:free`, key presence true. Port 8000 health is LIVE/ready. This is configuration verification, not a fresh provider/authentication test.
2. **Context shadowing in the test harness:** `seed_typed_organization_contexts()` imports complete TC02 and TC03 snapshots. The launched `scripts/dev.py --context context.json` subsequently imports the legacy demo snapshot. Read-only inspection of `.runtime/playwright-live/tc02-tc03-live-20261014-132557/app.sqlite` and `...-133110/app.sqlite` shows versions 1/2 have company name, one advance event and coverage; version 3 names both activities but has `company_name=null`, empty ledger and no coverage. `load_context` selects version 3 for each activity. Thus the runtime does not use the context the expected finance outcome assumes.
3. **Coverage finding rejected:** `admit_evidence` already uses `context_coverage(organization, ...)` when its explicit coverage argument is None. `organization.coverage` is a dictionary, whereas the explicit argument expects `CoverageRecord`. Blindly passing that dictionary is not a fix.
4. **Pure counterfactual:** reused the stored LIVE `ReadResult` from run 132557, no re-extraction. With the loaded legacy context, E/A/P/R/S are UNKNOWN. With the original typed context, still passing `coverage=None`, TC02 has E=5.4m/A=5m/S=+400k and TC03 E=A=4.32m/S=0. This proves context coverage is consumed. It does not certify the supplied future coverage or complete browser execution.
5. **Authority remains separate:** pure Reconciler evaluation of original typed contexts produces AUTHORITY `ISSUE_PAYMENT` for TC02 and no allowed effect. The harness has only approver actions `AUTHORIZE_EXPENSE/EXCEPTION_POLICY/AUTHORIZE_PAYMENT`, not the routine issuance authority assumed by PAY acceptance. TC03 has no issue and no financial effect. Fix context identity/history alone is not proof TC02 will autonomously issue PAY.
6. **Answer mismatch confirmed:** saved answers use `expense:payer`, while LIVE `_claim_index` consumes invoice-scoped `expense:<invoice_reference>:employee_paid`. Run 132557 stores numeric values; run 133110 stores actor ID for TC03. Both retain the payer issue. A generic actor dropdown does not itself resolve the typed consumer mismatch, and company-direct/partner choices expand the accepted employee-paid-only scope.
7. **Old crash vs current source:** `_activity_references` is defined in current `service.py`. The old NameError was observed during concurrent incomplete edits and cannot be reported as still present without reproduction. The harness monkeypatches this function, so its run is not an unmodified production-runtime acceptance check.
8. **Timeout wrapper ineffective:** assigning module constants and `XkiroClient.timeout_s=180` does not change the dataclass constructor default. A separate-process probe using those exact assignments then `build_llm_client(Settings())` still constructs timeout 60. Any timeout remedy must also account for the whole operation budget; increasing one timeout blindly is not justified.
9. **Browser result:** both inspected logs end in `2 failed`. Run 133110 TC02 fails on the expected `+400.000 ₫` draft text before submit (DB state DRAFT); TC03 fails because the answer textarea remains visible. Reload, instruction and late assertions after those failures are NOT_RUN for that attempt. A heading such as PARTIAL must not obscure these failures or merge different attempts into one completed workflow.

## Recommended next work

Repair the harness first: one validated, scoped context source survives startup; correct action grants; bounded and temporally responsible coverage; fresh frontend build matching tested source; no runtime monkeypatches in the acceptance run. Then rerun both original PDFs through Playwright LIVE and verify the server's actual loaded context. Keep the answer-consumer defect as a separate regression with invoice-specific values, provenance, ownership and bounds. Do not patch `coverage=None` into a raw dictionary, suppress FACT issues, or infer actual advances from PDFs alone.
